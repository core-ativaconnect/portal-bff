Chat WebSocket

Local: ws://localhost:3003/ws/webchat. Em produção, use o output ChatWebSocketUrl do deploy. A conexão WebSocket usa um host próprio; não acrescente este caminho à URL HTTP do Portal.

1. Conectar

Abra o WebSocket e envie um connect. O canal deve existir, ter um agente WEBCHAT e pertencer a um contrato ativo.

{"type":"connect","agentName":"agente-exemplo","contactName":"Visitante"}

O servidor responde com connected, contactId e contactToken. O histórico pode chegar em envelopes messages separados. Guarde o token para reconectar; um contactId sozinho não dá acesso a uma conversa.

2. Enviar e receber

{"type":"message","text":"Olá, preciso de ajuda"}

O servidor usa a sessão vinculada à conexão, inclusive para escolher agente e contato. As respostas do fluxo e do atendente chegam por push. Remova duplicatas pelo id de cada mensagem.

{"type":"messages","contactId":"contato-exemplo","messages":[{"id":"mensagem-exemplo","kind":"BUSINESS","text":"Como posso ajudar?","choices":[],"list":null,"occurredAt":"2026-09-11T12:00:00.000Z"}]}

3. Manter e retomar a sessão

Envie ping a cada 25 segundos. O servidor responde pong. Reconecte após o fechamento, reapresentando o contactToken:

{"type":"ping"}
{"type":"connect","agentName":"agente-exemplo","contactToken":"token-recebido-no-connected"}

O token dura 30 dias. A conexão AWS pode encerrar em até duas horas. Em erro 401, descarte o token inválido e inicie uma nova sessão. O JWT de login do Portal não é usado pelo chat público.

Mensagens do protocolo

DireçãotypeConteúdo
Cliente → servidorconnectagentName, contactName opcional, contactToken para retomada
Cliente → servidormessagetext obrigatório; até 20.000 caracteres
Cliente → servidorpingSem campos adicionais
Servidor → clienteconnectedcontactId, contactToken, agente e informações do canal
Servidor → clientemessagesLista com id, text, kind, choices, list e occurredAt
Servidor → clientepongConfirmação da sessão
Servidor → clienteerrorstatus e message; por exemplo 400, 401, 403, 404 ou 500

O protocolo HTTP legado de webchat aceita poll. O WebSocket aceita somente connect, message e ping.
